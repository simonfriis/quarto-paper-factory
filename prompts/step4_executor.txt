CRITICAL PRINCIPLE — ANALYTICAL COHERENCE: The existing R scripts were written by many independent agents who each made their own sample construction, variable definition, and measurement choices. Your most important job is to translate this patchwork into a single, internally consistent analysis. This means:

- ONE ANALYTICAL SAMPLE: Define one main estimation sample in the data build, with clear and consistent sample restrictions. Every main result, descriptive table, and figure should use this same sample unless the research design specifically requires otherwise (e.g., a different sample for a placebo test, or a restricted panel for an event study). When different agents used slightly different sample restrictions, pick the best one and apply it everywhere.
- ONE SET OF KEY VARIABLE DEFINITIONS: There should be one primary measure of the outcome variable and one primary measure of the key independent variable used throughout the main analysis. Different agents may have constructed these differently — pick the strongest definition and use it consistently. Alternative measures belong in robustness checks, clearly labeled as such.
- ONE DATA BUILD: Write a single, clean data construction R script (or a short sequence) that all subsequent analysis scripts depend on. Do not let each analysis script re-build the data from scratch with slightly different decisions. The build should save an analysis dataset (`.rds`) that downstream scripts and Quarto chunks load.
- ONE CLEAN DATA LAYOUT (MEDALLION): Keep immutable inputs separate from rebuildable products. Use `data/bronze/` for source artifacts and third-party inputs (raw exports, crosswalks, demographic enrichments, API pulls), `data/silver/` for typed analysis-ready tables, and `data/gold/` for analytical-decision outputs (aggregates, feature tables, final analysis datasets). Anything that must survive delivery belongs in `data/bronze/` or in code.
- CONSISTENT CONTROLS AND FIXED EFFECTS: The same set of controls and fixed effects should appear across the main specifications. When an extension agent added a new control or used a different clustering level, decide whether it belongs in the main specification or is a robustness variant — do not let specifications drift across scripts.
- ROBUSTNESS IS CLEARLY SECONDARY: Alternative samples, alternative measures, alternative specifications, and sensitivity tests should be clearly separated into robustness/appendix R scripts. The reader should never wonder which specification is the main one.

If you find that different agents' results are not directly comparable because they used different samples or variable definitions, RE-RUN the analyses with consistent choices rather than just stacking incompatible results.
