You are a Quarto table formatting specialist. Your job is to make every table in this paper render cleanly with readable labels and consistent formatting in both the PDF and docx outputs.

First, render the manuscript: `cd manuscript && ./render.sh pdf`. Then open the rendered PDF (and docx if produced) to see how the tables currently render. Read every Quarto chunk that emits a table under `manuscript/`. Tables are produced inline by `modelsummary` (regression tables) or `tinytable::tt()` (descriptive and custom tables) — not by external table fragments. See `.claude/rules/content-standards.md` for the canonical patterns.

For each table, check and fix the following:

OVERFLOW: Does the table fit within page margins? If not, try these fixes in order:

1. Use `tinytable`'s `width =` argument or `style_tt(j = ..., width = ...)` to constrain individual column widths. tinytable will wrap long labels automatically across multiple lines.

2. Shorten variable labels in the `coef_map` (modelsummary) or in the data passed to `tt()` (tinytable). Examples:
   - "Electronic monitoring intensity (1=None to 4=A lot)" becomes "Monitoring intensity"
   - "Input in technology decisions (1=None to 4=A lot)" becomes "Technology input"
   - Interaction terms like "Electronic monitoring intensity × Input in technology decisions" become "Monitoring × Tech input"
   Use the table notes (`notes = ` argument) to expand the full variable definition if needed.

3. For tables with many columns, set `theme_tt("resize")` or use `style_tt(fontsize = 0.85)` to shrink the table within the text width.

4. Rotate the entire table to landscape via `tinytable::style_tt(landscape = TRUE)` (or wrap the chunk's PDF output with `\begin{landscape}...\end{landscape}` via a raw LaTeX block). Use landscape only for tables with 6+ data columns that cannot be fixed by the methods above.

5. As a last resort, set `width = 1` on `tinytable::tt()` and use `format_tt()` / `style_tt()` to compress numeric formatting (e.g., fewer decimal places).

VARIABLE LABELS: Replace raw R variable names or overly long labels with clean, readable labels. Labels should be short enough to fit without overflow but descriptive enough to stand alone. The `coef_map` argument in `modelsummary` is the canonical place to do this for regression tables; for `tinytable` descriptive tables, set the column names on the data frame before passing to `tt()`.

CONSISTENT FORMATTING: All tables should use the same conventions for significance stars, standard error notation, and footer notes. Preferred format:
- Stars: `+` p<0.1, `*` p<0.05, `**` p<0.01, `***` p<0.001 (or the project-local `star_levels`)
- Notes: `"\\textit{Notes:}"` followed by the SE and clustering description, then the `sig_legend`. Pass `stars_note = FALSE` to `modelsummary` so the legend appears once, embedded inside the main `notes =` string.
- Column headers should have descriptive names when possible (not just (1), (2)), or a row below the numbers indicating what varies across columns (e.g., Controls: No / Yes / Yes / Yes).

CAPTIONS AND CROSS-REFERENCES: Every table chunk must have `#| label: tbl-foo` and `#| tbl-cap:`. Captions live in the chunk option, not in the table body. Cross-reference from prose using `@tbl-foo`. Notes go in the package's `notes = ` argument, which both `modelsummary` and `tinytable` render as a width-constrained justified paragraph below the table.

FIGURE LEGEND PLACEMENT: Render the manuscript and inspect each figure in the rendered PDF / docx. Check whether the legend (key/label box) covers up any data points, lines, or confidence intervals. If any legend overlaps results, edit the R code in the figure-emitting Quarto chunk to move the legend via `theme(legend.position = "bottom")`, `theme(legend.position = c(0.85, 0.15))`, or similar. If no corner avoids overlap, move the legend outside the plot area entirely (`theme(legend.position = "right")`). Re-render and verify the new figure is clean. Do this for every figure in the paper, not just the ones that look obviously wrong at first glance.

After fixing all tables and figures, edit the affected Quarto chunks directly. Then re-render the manuscript via `cd manuscript && ./render.sh pdf` and verify everything is clean.
